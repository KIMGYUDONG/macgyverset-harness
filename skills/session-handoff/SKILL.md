# Session Handoff

이 배포본은 사용 중인 개인 스킬과 지원 파일을 함께 옮긴 것이다. 실행 예시의 `<skill-dir>`는 이 SKILL.md가 있는 실제 폴더로 바꾼다. Python 3.10 이상이 필요하다. 시험에서는 작업 공간 안의 인계 파일만 작성하고 전역 메모리, hooks, 설정과 클립보드를 변경하지 않는다. 외부 전송과 자동 UI 조작을 하지 않고 후속 서술형 단계에서는 실행하지 않는다. 단일 교훈은 필요한 작업 공간 문서에만 남기며 설치되지 않은 joint 스킬을 요구하지 않는다.

현재 대화의 결정 이유와 로컬 증거를 함께 보존한다. 산출물을 지정하지 않은 세션 정리 요청에는 추천 메뉴를 먼저 제공하며, 이미 지정했다면 다시 묻지 않는다. 새 세션 자동 로드는 맥락 준비만 수행한다. 인계를 읽었다는 이유로 작업을 시작하거나 재개를 먼저 제안하지 않는다.

## 수집과 선택

1. 적용되는 AGENTS.md, 현재 대화, 관련 계획과 인계를 읽는다. 로컬 Git 상태와 실제 검증 결과를 확인한다. 홈 아래 모든 저장소를 검색하거나 GitHub 이슈와 PR을 일괄 조회하지 않는다. 원격 상태는 요청이 의존할 때 해당 대상만 확인한다.
2. 완료, 진행 중, 차단, 다음 단계, 핵심 파일, 결정과 이유, 제외한 대안, 교훈, 검증과 제약으로 다이제스트를 만든다. 대화에서만 확인된 주장과 현재 검증한 사실을 구분한다. 빈 범주는 생략하고 실패나 미확인 항목을 성공으로 바꾸지 않는다.
3. 선택이 없으면 [추천 가이드](references/triage-guide.md)를 읽고 네 산출물과 이번 세션의 추천 이유를 보여준다. 복수 선택 도구가 있으면 사용한다. 없으면 번호와 추천 조합을 제시해 사용자의 텍스트 선택을 받는다. 일반적인 '세션 정리'는 네 개 모두를 만들라는 뜻이 아니다. 비대화형 실행에서 선택이 없으면 추천만 반환하고 임의 생성하지 않는다.
4. 지정한 산출물만 작성한다. 완료 기준과 검증을 충족한 계획 항목만 완료 표시한다. 기억과 계획 수정은 현재 에이전트가 해당 파일의 기존 내용과 비교하여 수행한다.

## 산출물

- **인계 문서:** [다이제스트와 writer 인터페이스](references/writer-interface.md)를 읽고 완성된 JSON을 스크립트에 입력한다. `docs/handoff/`에 고유 Markdown과 `.handoff.json` 메타데이터가 저장된다. 결정 이유와 필요한 제외 대안을 보존한다. TODO 골격을 완성품으로 보고하지 않는다.
- **시작 프롬프트:** 자기완결된 현재 상태, 첫 작업, 제약과 남은 검증을 담는다. 선택하면 파일, 채팅 코드 블록, 클립보드에 제공한다. 시험에서는 파일과 채팅으로만 제공하고 `--copy`를 전달하지 않는다. 시험 밖에서 클립보드를 명시적으로 요청한 경우에만 `--copy`를 전달하고 반환값이 `copied`일 때 복사 성공을 말한다. 실패하면 파일과 채팅으로 제공한다. 이 프롬프트는 사용자가 붙여넣을 때 실행 지시가 되며 자동 로더에는 넣지 않는다.
- **교훈 정리:** [기억 정리 기준](references/memory-schema.md)에 따라 이미 저장된 교훈을 확인하고 중복을 병합한다. 세션 진행 상황은 인계에 둔다. 백그라운드 메모리를 활성화하지 않는다.
- **계획과 지침 갱신:** 관련 계획 수용 기준을 실제 결과와 대조해 상태와 근거를 갱신한다. 거의 완료, 테스트 일부 통과는 완료가 아니다. 시험에서는 규칙과 교훈을 작업 공간 안에만 남기며 전역 파일과 joint 절차를 사용하지 않는다. 시험 밖에서 전역 갱신을 명시적으로 요청한 경우에만 해당 환경의 기존 절차를 따른다.

## 실행과 보고

```bash
python3 <skill-dir>/scripts/create_session_handoff.py \
  --repo /path/to/project --input /path/to/digest.json \
  --artifacts handoff,kickoff
```

`--artifacts`는 필수이며 `handoff`, `kickoff` 또는 두 항목을 받는다. 교훈과 계획만 선택했다면 writer를 실행하지 않는다. 변경한 파일 링크와 실제 검증 상태를 보고한다. 시작 프롬프트를 선택했다면 채팅에도 전체 프롬프트를 제공한다. 훅 파일 존재나 등록과 실제 새 세션 로딩 검증은 구분한다. 이 스킬을 실행할 때마다 훅을 설치하거나 설정을 바꾸지 않는다.

원본 Claude 스킬에서 가져온 선택 메뉴, 다이제스트, 결정 보존, 클립보드 절차와 교정한 평가 사례는 [행동 평가와 출처](references/behavior-evals.md)에 있다. 스킬 변경 후 형식 검사와 writer 회귀 검사, 필요한 실제 사용 평가를 구분해 수행한다.

자동 로더의 현재 선택 기준과 레거시 호환 범위는 [writer와 loader 계약](references/writer-interface.md)에 있다. Claude 진입점도 같은 공유 writer와 로더를 사용하며, 일반 인수인계 실행에 훅 설치를 포함하지 않는다.
