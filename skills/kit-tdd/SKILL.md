# 실패 재현부터 구현

1. 기존 테스트 관례를 읽고 호출자에게 보이는 동작 하나를 고른다.
2. 실제 구현 경로를 거치는 최소 테스트를 작성한다. 정상 경로와 중요한 오류/경계를 구분한다.
3. 테스트를 실행해 기대한 이유로 실패했는지 확인한다. 문법 오류나 의존성 누락은 동작의 실패 재현이 아니다.
4. 테스트를 통과시키는 최소 구현을 만든다.
5. 대상 테스트와 영향을 받을 기존 기능 검사를 실행한다.
6. 통과 상태에서 필요한 정리만 하고 변경한 부분을 다시 확인한다.

검증은 결과와 사용자 동작을 검사한다. 구현의 문자열이나 내부 호출 횟수를 그대로 비교하지 않는다. 시간, 네트워크와 외부 서비스는 필요한 경계에서만 대체한다. 외부 서비스 모형의 통과를 실제 서비스 확인으로 보고하지 않는다.

문서, 단순 설정, 생성 코드와 되돌리기 쉬운 저위험 변경에 무의미한 테스트를 추가하지 않는다. 테스트를 실행할 수 없으면 원인과 남은 확인을 밝히고 통과를 주장하지 않는다. UI 자동 조작은 수행하지 않는다.
