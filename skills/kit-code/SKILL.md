# 구현

관련 코드와 테스트 관례를 먼저 확인한다. 기존 소스와 사용자 변경을 보존하고 작은 동작 단위로 수정한다. 전체 앱 템플릿을 가져와 기존 과제 결과물을 대체하지 않는다.

중요한 동작 변경과 버그는 사용 가능한 테스트 도구로 실패를 먼저 재현한다. 구현을 복제하는 테스트와 목 호출 횟수 검사에 치우치지 않는다. 기존 프레임워크와 의존성을 우선하고 새 의존성은 필요한 만큼만 추가한다.

독립 작업을 네이티브 에이전트에 맡길 때는 소유 파일, 요구 동작, 완료 검사와 다른 작업자의 존재를 명시한다. 동시 자식은 기본 2개 이하, 같은 파일 수정자는 한 명으로 둔다. 위임 도구가 없으면 메인이 수행한다. 다른 AI CLI와 개인 API로 대체하지 않는다.

화면은 기존 디자인 시스템과 컴포넌트를 먼저 재사용한다. 없으면 색상, 글자 크기, 간격과 로딩/빈 상태/오류 상태를 간단히 정한다. 과제의 실제 사용자가 이해하는 용어와 행동을 보여주고 개발 내부 설정을 화면에 불필요하게 노출하지 않는다.

웹 서버는 플랫폼 안내에 맞는 포트와 0.0.0.0 바인딩으로 실행하고 유지한다. 터널과 외부 배포를 만들지 않는다. UI는 사용자가 플랫폼 Browser로 직접 확인하고, CLI/API 검증과 수동 화면 확인을 구분해 기록한다. Computer Use, Playwright, agent-browser와 CDP 자동 조작은 사용하지 않는다.
