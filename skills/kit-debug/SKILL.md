# 체계적 디버깅

`harness-official/skills/systematic-debugging/SKILL.md`가 있으면 먼저 읽고 필요한 부분만 적용한다. 없으면 아래 절차를 쓴다. 이 키트의 시험 경계가 원문보다 우선한다. 브라우저 자동 조작, 외부 전송, 별도 런타임 설치는 원문이 권해도 하지 않는다.

1. 재현한다. 명령과 입력을 고정하고 실패 출력을 저장한다. 재현하지 못하면 원인을 추측하지 않는다.
2. 증거를 모은다. 오류 메시지, 로그, 최근 변경, 입력값, 경계 위치를 확인한다.
3. 가설을 하나씩 세운다. 한 번에 하나만 검증하고 결과를 기록한다.
4. 원인에 해당하는 최소 수정을 한다. 겸사겸사 고치지 않는다.
5. 재현했던 실패를 회귀 테스트로 남긴다(kit-tdd). 영향받는 기존 검사를 실행한다.
6. board에 `증상 / 원인 / 수정 / 근거`를 기록한다.

수정이 3번 실패하면 멈추고 가설과 구조 이해를 다시 점검한다. 필요하면 지휘 창에 요청한다.

화면 문제는 자동 조작 없이 서버 로그, API 응답, 사용자가 Browser에서 확인한 현상으로 좁힌다.
