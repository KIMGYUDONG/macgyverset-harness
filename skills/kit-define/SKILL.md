# 문제 정의와 담당자 질문

[템플릿](../../templates/problem-definition.md)에 아래 항목을 짧게 채운다. 과제 안내와 기존 코드로 알 수 있는 항목은 먼저 채우고 질문에 넣지 않는다.

- 누가 쓰는가, 어떤 업무인가
- 지금 불편한 점
- 원하는 결과
- 성공 기준(확인할 수 있는 문장)
- 산출물 유형: 프로그램, 분석, 제안 중 무엇인가
- 제약: 시간, 환경, 사용 가능한 도구
- 기존 시스템과 바뀐 조건의 차이

## 담당자 질문

담당자 에이전트는 사용자가 플랫폼에서 직접 묻는다. 질문은 사용자가 그대로 붙여 넣을 수 있게 작성하고 번호를 붙인다. 한 번에 묶어 묻는다. 답은 `docs/board/lead.md`에 붙여 넣는다.

| 범주 | 묻는 것 |
|---|---|
| 기존 데이터의 특이점 | 빈 값, 중복, 예외 코드, 이상한 값의 의미 |
| 역할별 화면 | 역할마다 꼭 봐야 하는 정보와 하는 일 |
| 입력과 출력 | 입력 형식, 출력 형식, 단위, 정렬 기준 |
| 엣지 케이스 | 규칙이 충돌할 때, 한도를 넘을 때, 데이터가 없을 때 |
| 우선순위 | 반드시 되어야 하는 것과 나중에 해도 되는 것 |

질문 수를 늘리지 않는다. 답이 설계를 바꾸지 않는 질문은 지운다. 데이터가 있으면 먼저 kit-data로 확인하고 질문에 근거를 붙인다.
