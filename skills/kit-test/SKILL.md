# 세 층 테스트

| 층 | 소유 | 대상 | 방법 |
|---|---|---|---|
| 단위 | 2번 창 | 함수/도메인 동작 | kit-tdd |
| 시나리오와 API E2E | 4번 창 | 경계/오류 시나리오, 관리자가 ID를 만들고 이용자가 쓰는 흐름 | HTTP 호출 스크립트 (`tests/e2e/`) |
| 부하 | 4번 창 | 동시 요청의 지연과 오류 | k6 또는 대체 스크립트 (`tests/load/`) |

## 중복 방지

4번 창은 시작 전에 2번 창의 테스트 목록(board/feature.md)을 읽는다. 단위로 이미 확인된 동작은 시나리오에서 다시 쓰지 않는다. 시나리오는 여러 API가 이어지는 흐름과 규칙이 충돌하는 경계에 둔다.

## 증거

- 실행한 명령, 종료 상태, 통과/실패 수
- 부하는 요청 수, 동시성, p50, p95, 오류율, 실행 환경(로컬)
- 화면은 사용자가 Browser에서 확인한 항목과 결과를 따로 기록한다. HTTP 통과를 화면 확인으로 보고하지 않는다.

## 부하 도구

`k6 version`으로 설치를 확인한다. 없으면 설치하지 않고 Python 표준 라이브러리(`concurrent.futures`, `urllib.request`)로 동시 요청을 보내 지연의 p50/p95와 오류율을 출력하는 작은 스크립트를 쓴다. 시험 환경 안의 로컬 서버만 대상으로 한다.

## 기록

결과는 `docs/board/test.md`에 시나리오별로 남긴다. 실패는 재현 명령과 함께 담당 창에 요청하고, 수정 후 같은 명령으로 다시 확인한다. 변경이 없으면 전체 검사를 반복하지 않는다.
