# 과제 정의와 계획

과제 안내, README, 적용 지침과 관련 코드부터 읽는다. 목표, 필수 산출물, 입력/출력, 제한 시간과 검증 방법을 짧게 묶는다. 코드로 알 수 있는 사실을 사용자에게 묻지 않는다.

새 데이터나 동작을 추가할 때는 실제로 필요한 입력 계약, 저장/상태의 소유권, 실패 시 결과를 확인한다. 결과를 바꾸는 미결정 사항만 질문하고, 선택을 위임받으면 가장 단순한 방식을 근거와 함께 선택한다. 불필요한 관리 화면, 범용 계층과 미래 확장을 만들지 않는다.

핵심 흐름을 먼저 완성할 수 있게 작업을 나눈다. 각 작업에 관찰 가능한 완료 기준과 필요한 검사 한두 개를 연결하고, 독립 작업과 선행 작업을 구분한다. 변경 범위가 작으면 대화의 짧은 체크리스트로 충분하다. 요구가 확정되면 반복 승인 없이 허용된 구현과 검증으로 이어간다.
