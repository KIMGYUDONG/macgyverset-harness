# 알려진 함정

지난 시험과 작업에서 막힌 지점이다. 해당할 때만 읽는다.

## 프록시 뒤 서비스에 접근이 안 될 때

- 서버는 `0.0.0.0`에 바인딩하고 포트를 고정한다. `localhost`에만 묶지 않는다.
- 프런트의 API 주소는 상대 경로(`/api/...`)로 쓴다. 절대 주소(`http://localhost:...`)를 넣지 않는다.
- 플랫폼이 하위 경로로 서비스를 열면 base path를 맞춘다. Vite는 `base`, `server.host`, `server.allowedHosts`를 확인한다. 다른 도구는 같은 의미의 설정을 찾는다.
- 프런트와 백엔드 포트가 다르면 개발 서버 프록시 또는 CORS 허용을 설정한다.
- 서버를 띄운 뒤 `curl`로 포트 응답을 확인한다. 응답이 있으면 플랫폼 URL을 사용자가 Browser에서 연다.
- 확정한 URL과 포트는 `docs/board/run.md` 상단에 기록한다. 바뀌면 즉시 갱신한다.

## React Flow 노드가 겹칠 때

- 노드에 너비와 높이를 명시한다(스타일 또는 `width`, `height`). 크기 없이 위치만 주면 겹친다.
- 자동 배치는 dagre나 elkjs가 이미 있거나 설치가 허용될 때만 쓴다. 아니면 인덱스로 계산한 격자 좌표(`x = col * (width + gap)`, `y = row * (height + gap)`)를 쓴다.
- `fitView`를 켜고 노드 수가 많으면 `minZoom`을 낮춘다.
- 겹침은 자동 검사하기 어렵다. 사용자 Browser 확인 항목에 넣는다.

## 디자인

- shadcn 컴포넌트를 먼저 쓴다.
- 과제가 준 브랜드 자산이 있으면 그것을 우선한다. 없으면 SK hynix 계열 빨강/주황 토큰 한 벌을 CSS 변수로 정의한다.
- 글자와 배경의 대비를 지킨다. 강조색은 행동 버튼과 상태 표시에만 쓴다.

## 브라우저 자동화 없이 E2E

- 흐름은 HTTP로 검증한다. 예: 관리자 로그인, 이용자 ID 생성, 그 ID로 로그인, 핵심 조회/변경, 결과 확인.
- 화면 확인은 항목 목록을 만들어 사용자가 Browser에서 직접 확인한다.
- 보고에서 두 가지를 구분한다. "HTTP 시나리오 통과"와 "사용자가 화면에서 확인함"은 다른 증거다.

## 테스트가 겹칠 때

단위는 2번 창, 시나리오/E2E/부하는 4번 창이다. 4번 창은 단위로 이미 확인된 동작을 반복하지 않는다. 자세한 내용은 [kit-test](../skills/kit-test/SKILL.md).
