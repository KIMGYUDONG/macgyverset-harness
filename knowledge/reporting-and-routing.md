# 팀장에게 보고하는 방식

사용자가 프로젝트 흐름을 따라가며 결정할 수 있도록 쉬운 한국어로 보고한다. 내부 도구 호출 목록이나 긴 코드 설명 대신 사용자가 보게 될 결과와 현재 상태를 말한다. 설명 없이 오래 작업하지 않는다.

- **작업 전:** 무엇을 왜 할지, 무엇으로 확인할지 2-3문장으로 말한다. 예: "로그인 오류를 재현한 뒤 원인을 고치겠습니다. 정상 로그인과 만료된 세션을 함께 확인하겠습니다."
- **작업 중:** 의미 있는 발견이나 방향 변경, 약 1분 이상 걸리는 작업은 "현재 상태 / 확인한 사실 / 다음 작업"을 짧게 보고한다. 대기 자체를 진행률로 표시하지 않는다.
- **결정 필요:** 결과가 달라지는 선택만 배경과 추천안을 함께 제시한다. 이미 결정한 사항과 코드로 알 수 있는 사실은 다시 묻지 않는다.
- **작업 후:** "결과 / 확인 근거 / 남은 일" 순서로 정리한다. 실패와 미검증을 숨기지 않으며, 완료하지 않은 일을 완료로 보고하지 않는다. 남은 일이 없으면 빈 항목을 채우지 않는다.

숫자 진행률을 추측하지 않는다. 식별자와 파일명은 근거가 필요할 때만 쓰고, 약어는 처음에 쉬운 말로 설명한다. 사용자에게 중요한 변화와 선택 이유를 연결한다. 자식 에이전트도 같은 보고 계약을 따르고 메인은 결과를 묶어 사용자에게 보고한다.

# 모델과 reasoning effort 선택

속도와 품질을 함께 고려해 작업을 작게 나누고 필요한 추론 수준을 선택한다. 이는 측정된 속도 향상 보장이 아닌 시작 기준이다. 제공된 Codex의 실제 모델 목록과 지원되는 effort만 사용하며 버전, 제공자와 권한을 변경하지 않는다.

| 작업 | 시작 모델 | 시작 effort |
|---|---|---|
| 명확한 파일 찾기, 짧은 분류와 요약 | 제공된 Luna 6.0 | low 또는 지원 최저 수준 |
| 범위가 정해진 일반 구현과 테스트 작성 | 제공된 Sol 6.1 | medium |
| 원인이 불명확한 버그, 데이터 계약과 구조 판단 | 제공된 Sol 6.1 | high |
| 변경 결과의 독립 검증과 중요한 경계 검토 | 제공된 Sol 6.1 | high |
| 단순 문구 수정과 포맷 정리 | 제공된 Luna 6.0 | low 또는 지원 최저 수준 |

Luna가 없으면 사용 가능한 Sol 6.1로 수행한다. Sol이 없으면 운영 안내에서 허용되고 제공된 Terra 5.6을 사용한다. 정확한 모델 ID와 effort 지원 여부는 제공 환경에서 확인한다. 지원하지 않는 effort는 그 모델의 기본값으로 두고 임의 별칭을 설정하지 않는다. Astra와 Fable, Claude Code, 개인 API와 외부 모델은 사용하지 않는다.

메인은 기본 Sol 6.1/medium에서 시작하고 어려운 판단에만 high를 선택한다. 자식을 만들 때 모델과 effort를 명시해 실제 적용 값을 확인한다. 적용값을 확인할 수 없으면 위임하지 않는다. 탐색 실패나 요구사항 누락이 드러나면 작업 범위를 좁히거나 effort를 한 단계 높인다. 단순 응답 대기만으로 같은 요청을 여러 에이전트에 중복시키지 않는다. 복잡한 판단을 낮은 effort로 반복하는 것과 모든 작업을 가장 높은 effort로 처리하는 것을 피한다.

작업 시작 때 선택 이유를 한 줄로 보고한다. 예: "구현은 Sol의 중간 추론으로 진행하고, 마지막 경계 검사는 높은 추론으로 맡기겠습니다." 실제로 설정하지 않았다면 설정했다고 말하지 않는다.
