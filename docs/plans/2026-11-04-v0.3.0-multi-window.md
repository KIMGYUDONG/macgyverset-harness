## 확정 설계
### 1. 창 5개 역할 카드 (`cards/1-lead.md` ~ `cards/5-run.md`)
사용자는 각 창에서 `codex` 실행 후 카드 한 장을 붙여넣기만 한다(카드 안에 "macgyverset-harness/cards/N-*.md를 읽고 따르라" 한 줄 진입문 제공).

| 창 | 역할 | 쓰는 파일(단독 소유) | 읽는 파일 |
|---|---|---|---|
| 1 지휘 | 과제/기존 시스템 파악, 담당자 질문 목록, PRD/ADR/Edge/최적화(필요한 것만, 각 1쪽), 작업 배정 | `docs/board/lead.md`, `docs/prd.md` 등 | 모든 board |
| 2 기능 | API/도메인 로직, kit-tdd로 동작 단위 테스트 | 배정된 백엔드 파일, `docs/board/feature.md` | lead.md |
| 3 화면 | UI(shadcn, SK하이닉스 색), 역할별 화면 | 배정된 프론트 파일, `docs/board/ui.md` | lead.md, prd |
| 4 테스트 | 기능 테스트 보강(창2 단위 테스트와 중복 금지: 시나리오/경계 위주), API E2E(관리자 ID 생성 -> 이용 흐름), 부하(k6 있으면 k6, 없으면 내장 스크립트) | `tests/e2e`, `tests/load`, `docs/board/test.md` | lead.md, edge |
| 5 실행 | 서버 기동, 프록시/포트 문제 해결, 매뉴얼 3종, 제출 점검 | 실행 설정, `docs/manuals/*`, `docs/board/run.md` | 모든 board |

- 게시판 규칙: 창마다 자기 board 파일만 쓴다(동시 쓰기 충돌 방지). 지휘만 결정과 배정을 쓴다. 상태 형식: `[시각] 상태 / 한 일 / 근거(명령, 결과) / 다른 창에 요청`.
- 창 안 서브에이전트: 창당 동시 3개까지(플랫폼 최대). 독립 조사/검증/별도 파일 구현에만. RAM 16GB와 "AI 사용량 평가" 때문에 작은 일은 메인이 한다.

### 2. 단계 게이트 (`knowledge/workflow.md`, 시간표 없음)
각 단계: 할 일 / 완료 조건 / 건너뛰기 조건("이 과제에 필요 없으면 생략하고 이유 한 줄").
S0 설치와 파악 -> S1 문제 정의와 담당자 질문 -> S2 필요한 문서 -> S3 병렬 구현 -> S4 테스트 -> S5 매뉴얼과 제출. 각 단계 시작/끝에 팀장 보고.

### 3. 새 스킬 (kit-* 접두어라 prepare.py 자동 포함)
- `kit-define`: 문제 정의 양식 + 담당자 에이전트 질문 목록(기존 데이터 특이점, 역할별로 보여야 할 것, 입출력). 산출물 유형(프로그램/분석/개선안) 판별. PRD/ADR/Edge/최적화 1쪽 템플릿은 `templates/`.
- `kit-data`: `scripts/profile_data.py`(표준 라이브러리 CSV, openpyxl 있으면 XLSX): 행/열, 결측, 중복, 날짜 범위, 수치 범위, 이상값 상위 N.
- `kit-debug`: 공식 systematic-debugging을 시험 경계에 맞춘 어댑터(재현 -> 원인 -> 가설 검증 -> 최소 수정 -> 회귀 테스트).
- `kit-test`: 테스트 3층(창2 단위 / 창4 시나리오+API E2E / 부하) 역할 분리, k6 대체 스크립트 기준.
- `kit-manual`: 매뉴얼 3종 템플릿(관리자, 이용자, 심사 에이전트용 실행/검증 안내).
