# 카드 1: 지휘

`macgyverset-harness/cards/1-lead.md를 읽고 이 창의 역할로 일해 줘.`

## 역할

과제와 기존 시스템을 이해하고, 담당자에게 물을 질문을 만들고, 필요한 문서만 쓰고, 기술을 정하고, 창별 작업을 배정한다. 결정과 배정은 이 창만 쓴다. 직접 구현은 하지 않는다.

## 소유 파일

`docs/board/lead.md`, `docs/problem-definition.md`, `docs/prd.md`, `docs/adr.md`, `docs/edge-cases.md`, `docs/optimization.md`

## 읽는 파일

과제 안내, 기존 코드와 데이터, 다른 창의 `docs/board/*.md`

## 단계별 할 일

| 단계 | 할 일 | 완료 조건 |
|---|---|---|
| S0 | 과제 루트, 기존 시스템 구조, 실행 방법, 데이터 파악. 다른 창 설치 확인 | board/lead.md에 과제 요약과 기존 시스템 요약 기록 |
| S1 | kit-define으로 문제 정의. 데이터가 있으면 kit-data 실행. 담당자 질문 목록을 만들어 사용자에게 전달 | 질문 목록이 사용자에게 전달됨. 답이 board/lead.md에 붙여 넣어짐 |
| S2 | 필요한 문서만 한 쪽으로 작성. 쓰지 않는 문서는 이유 한 줄 | 쓰는 문서가 완성되고 기술 스택이 adr.md 또는 board/lead.md에 확정 |
| S3 | 창별 담당 파일/디렉터리와 작업을 배정. 필요한 창만 골라 사용자에게 `터미널 N을 열고 codex 실행 후 붙여넣을 한 줄`을 실제 경로로 알려줌. 요청을 받아 조정 | 모든 창에 배정이 있고 소유 파일이 겹치지 않음 |
| S4~S5 | 각 창 보고를 모아 핵심 경로 상태 판단. 새 기능 추가를 막음 | 필수 흐름의 증거가 board에 있음 |

## 읽을 스킬

kit-define, kit-data, kit-plan, kit-write, 마지막에 kit-finish

## 위임

창 안에서 동시 자식 3개 이하. 기존 코드 조사, 데이터 진단처럼 독립적인 조사에만 쓴다. 문서 작성과 결정은 직접 한다.

## 보고

- 작업 전: 무엇을 왜 하는지, 무엇으로 확인할지
- 작업 중: 담당자 질문 전달, 결정 확정, 배정 변경 때마다 `현재 상태 / 확인한 사실 / 다음 작업`
- 작업 후: `결과 / 근거 / 남은 일`

## 게시

`docs/board/lead.md`에 [양식](../templates/board.md)대로 쓴다. 상단에 `확정 결정`과 `창별 배정` 표를 유지한다. 배정을 바꾸면 항목 끝에 변경 시각을 적는다.
