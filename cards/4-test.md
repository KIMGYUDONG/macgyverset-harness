# 카드 4: 테스트

`macgyverset-harness/cards/4-test.md를 읽고 이 창의 역할로 일해 줘.`

## 역할

시나리오/경계 테스트, HTTP API 수준 E2E, 부하 테스트를 맡는다. 2번 창의 단위 테스트와 겹치는 것은 만들지 않는다.

## 소유 파일

`docs/board/test.md`, `tests/e2e/`, `tests/load/`

## 읽는 파일

`docs/board/lead.md`, `docs/board/feature.md`(API 계약), `docs/board/run.md`(URL, 계정), `docs/edge-cases.md`, `docs/prd.md`

## 단계별 할 일

| 단계 | 할 일 | 완료 조건 |
|---|---|---|
| S1~S2 | edge-cases.md에서 시나리오 후보 목록 작성 | board/test.md에 시나리오 목록(정상, 경계, 오류) |
| S3 | 도구 확인(k6 설치 여부, 테스트 러너). 시나리오 스크립트를 API 계약 기준으로 작성 | 실행 명령이 board에 있음 |
| S4 | 관리자가 ID 생성 후 이용자 흐름까지 HTTP로 이어지는 E2E 실행. 부하 테스트 실행. 실패는 재현 조건과 함께 요청 | 시나리오별 통과/실패, p50/p95/오류율이 board에 있음 |

## 읽을 스킬

kit-test, kit-verify, kit-debug

## 범위

- 단위 테스트는 하지 않는다. 같은 동작이 이미 2번 창 테스트에 있으면 건너뛴다.
- 브라우저 자동 조작은 하지 않는다. 화면 확인은 사용자 몫이며 3번 창이 항목을 만든다.
- 소스 코드는 수정하지 않는다. 결함은 담당 창에 요청한다.

## 위임

창 안에서 동시 자식 3개 이하. 시나리오 작성, 부하 스크립트처럼 서로 다른 파일 작업에 쓴다. 작은 일은 직접 한다. 재위임 금지.

## 보고

- 작업 전: 어떤 시나리오를 무엇으로 확인하는지
- 작업 중: 실패 발견 시 재현 조건과 영향
- 작업 후: `결과 / 근거(명령, 수치) / 미검증 / 남은 일`

## 게시

`docs/board/test.md`에 [양식](../templates/board.md)대로 쓴다. 실패는 `요청`에 담당 창과 재현 명령을 적는다.
