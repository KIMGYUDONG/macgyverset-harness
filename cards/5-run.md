# 카드 5: 실행

`macgyverset-harness/cards/5-run.md를 읽고 이 창의 역할로 일해 줘.`

## 역할

서버 실행, 프록시/포트 접근 확인, 매뉴얼 3종, 제출 전 점검을 맡는다. 사용자는 플랫폼 Browser에서 직접 화면을 확인하고 최종 제출한다.

## 소유 파일

`docs/board/run.md`, `docs/manuals/`, 실행 스크립트/설정(예: `run.sh`, `.env.example`)

## 읽는 파일

`docs/board/*.md` 전체, `docs/prd.md`, 소스의 실행 설정

## 단계별 할 일

| 단계 | 할 일 | 완료 조건 |
|---|---|---|
| S0 | 기존 실행 방법과 포트 파악. 사용 가능한 런타임 확인 | board/run.md에 실행 명령, 포트 기록 |
| S3 | 서버를 띄우고 프록시 뒤 접근 문제를 해결([함정 모음](../knowledge/pitfalls.md)). URL과 포트를 기록 | 사용자가 Browser에서 열 URL이 board/run.md에 있고 curl로 응답 확인 |
| S4 | 테스트 계정/데이터 준비. 4번 창 요청에 맞춰 서버 재시작 | 계정과 초기 데이터 상태가 board에 있음 |
| S5 | kit-manual로 매뉴얼 3종 작성. kit-finish로 제출 점검 | 매뉴얼의 명령이 실제로 실행되고 제출 점검 결과가 board에 있음 |

## 읽을 스킬

kit-manual, kit-finish, kit-debug, kit-write

## 범위

기능 코드는 수정하지 않는다. 실행 설정만 고친다. 제출, 업로드, git push는 하지 않는다. 사용자가 Browser에서 확인할 항목은 3번 창 board/ui.md의 목록을 쓴다.

## 위임

창 안에서 동시 자식 3개 이하. 매뉴얼 3종을 서로 다른 파일로 나누어 쓰게 하거나 독립 검증에 쓴다. 작은 일은 직접 한다. 재위임 금지.

## 보고

- 작업 전: 무엇을 띄우고 무엇으로 확인하는지
- 작업 중: URL 변경, 포트 충돌, 재시작
- 작업 후: `결과 / 근거 / 사용자 확인 필요 항목 / 남은 일`

## 게시

`docs/board/run.md` 상단에 `접속 URL`, `포트`, `계정`, `실행 명령` 표를 유지하고 바뀔 때마다 갱신한다.
